# 统一登录接入

实施方案：同一 HTTPS IP 入口下的独立前端共享后端会话。新登录外壳采用用户选定的深蓝方案；原型比较保留在 `codex/prototype-unified-login` 的 `d1366c4`，不进入正式功能分支。

## 前端行为

- `/login` 使用邮箱/用户名、密码、记住此设备，创建 `/api/auth/session`。不读取 Cookie、不保存 access/refresh token，不自动刷新 JWT 或重放写操作。
- `/apps` 显示后端允许的项目，并管理自己的登录设备。普通用户无后台入口，dsh 单独授权给 tuanzi。
- `returnTo` 与旧 `redirect` 仅允许本站登记项目路径，登录后整页进入独立前端。外站、反斜杠、登录循环及 API 路径退回工作台。
- Axios 始终使用本站 `/api`；写请求附加 CSRF，所有响应按身份代际校验。401 清理，403 保留会话，网络/5xx 显示重试错误。
- 身份变化时取消查询、清缓存并重新挂载应用，防止旧画布、生成状态、会话内容或迟到响应进入新身份。
- 生产切换后关闭旧登录、刷新与注册协议；`/register` 保留地址并跳转统一登录。首版使用已有账号，后续开放注册需增加对应会话协议。

`src/lib/browser-session.ts` 是协议 v1 客户端，各独立仓库保留对应副本；它没有 Vue/Pinia 依赖，变化需同步四份，并运行跨项目联调。外壳与正式表单分开，未保留演示提交或方案切换器。

## 验证

- 本地构建、lint 通过；隔离浏览器验证真实会话/CSRF 控制器、四前端同源共享、普通账号拒绝后台但保持登录、HttpOnly/无本地 token、跨项目退出、换号和全部设备撤销。
- 联调命令：先构建四个前端及后端，再运行 `AUTH_FIXTURE_BACKEND=<后端工作区绝对路径> pnpm test:session-browser`。测试只使用回环服务、内存测试账号和临时日志，不读生产数据库。
- 用户随后明确授权推送与部署。后端完整 CI 与真实 MySQL 迁移校验通过，后端和三个线上前端已通过 Actions 发布。正式 IP 证书及续期演练通过，HTTP 跳转 HTTPS，dsh 全量请求改经统一会话网关。现网只使用新启动捕获流程，不读取历史日志凭据。
- 线上验证覆盖真实共享身份、HttpOnly/无本地 token、dsh 认证交接及跨项目退出；验证使用最终删除的短期会话，浏览器隔离日记/观察池业务写操作，不发送 dsh 命令。管理后台按用户决定仅保留本地，线上地址展示尚未发布说明。
- 修正 HTTPS 发布健康检查、root 认证文件加载及主站 rsync 文档保留：认证配置由应用只读挂载，宿主机保持 root 0700/0600，发布账号不读取密钥；主站不删除独立发布的 documents。

## 发布与回退

先发布会话后端、执行新增 DDL、启用 HTTPS 和服务器受保护认证配置，再发布各前端。生产期间禁用本机 HTTP 例外。旧登录页面在其他项目只保留跳转入口。本轮三个线上前端完成迁移后关闭 legacy。

后端详细方案与 Nginx/证书/dsh 准备见 server-base 的 `docs/plans/2026-11-04-unified-browser-auth.md`。数据不迁移、不改用户 ID。前后端需协调回退；先重新启用旧协议，再恢复旧前端，不能只恢复令牌存储。未经验证不合并生产分支。
